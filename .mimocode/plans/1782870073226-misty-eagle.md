# FlashSaleCoreServicePractice 学习优化计划

## 目标
将练习版（FlashSaleCoreServicePractice）从简化版逐步升级为能跑通完整秒杀流程的版本，每阶段学习一个核心组件。

## 当前状态
练习版代码（174行）：直接MySQL查询，无缓存/MQ/限流。

## 分阶段学习路径

### Phase 1: Redis Lua 原子扣减库存 ⭐ 第一步
**目标**：用 Redis Lua 脚本替换 MySQL 乐观锁扣减
**学习重点**：Redis 原子操作、Lua 脚本在 Redis 中的执行机制
**改动**：
- 复用已有的 `flash_deduct.lua` 脚本
- 在 `FlashSaleCoreServicePractice.buy()` 中，将 MySQL `UPDATE ... WHERE stock > 0` 替换为 Redis Lua 脚本调用
- 添加 warmup 方法：活动开始前将库存加载到 Redis
**验证**：能通过 Redis 原子扣减库存，不会超卖

### Phase 2: Redis Pub/Sub 本地缓存同步
**目标**：添加 JVM 本地库存缓存，用 Redis Pub/Sub 多实例同步
**学习重点**：本地缓存 vs 分布式缓存、Pub/Sub 消息广播
**改动**：
- 添加 `ConcurrentHashMap<Long, AtomicLong>` 本地库存快照
- 添加 Redis Pub/Sub 监听器，同步库存变更
- 快速拒绝：本地库存为0时直接返回
**验证**：多请求并发时本地缓存正确更新

### Phase 3: RocketMQ 异步下单
**目标**：用 MQ 解耦下单流程，实现削峰
**学习重点**：异步消息、最终一致性、幂等处理
**改动**：
- 复用已有的 `FlashOrderPublisher` 和 `FlashOrderMqListener`
- 在 `buy()` 成功后，通过 MQ 发送下单消息
- 添加同步降级：MQ 不可用时回退到同步下单
**验证**：MQ 异步下单成功，MQ 不可用时能降级

### Phase 4: 滑动窗口限流
**目标**：添加基于 Redis 的滑动窗口限流
**学习重点**：限流算法、Redis Sorted Set + Lua
**改动**：
- 复用已有的 `sliding_window_limit.lua`
- 在 `buy()` 前添加限流检查
- 简单的黑名单机制
**验证**：超过频率限制的请求被拒绝

### Phase 5: 熔断降级
**目标**：添加 Resilience4j 熔断器
**学习重点**：熔断模式、降级策略
**改动**：
- 为 Redis 调用添加 `@CircuitBreaker`
- Redis 失败时降级到 MySQL 乐观锁（带限速）
**验证**：Redis 不可用时自动降级到 MySQL
