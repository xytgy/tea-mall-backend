# 登录接口限流检查顺序调整 — 实现计划

## 目标

让登录接口优先返回对用户有意义的错误（账号锁定），同时防止用户枚举攻击。

## 核心改动

### 1. 修改 `RateLimitService.java` — `isAccountLocked` 返回剩余锁定时间

**当前：** 返回 `boolean`
**改为：** 返回 `long`（剩余锁定秒数，0=未锁定）

```java
// 新方法
public long getAccountLockRemaining(String identifier) {
    return RedisSafeRunner.execute(() -> {
        String lockKey = keyPrefix + LOGIN_RATE_PREFIX + identifier + ":lock";
        Long ttl = stringRedisTemplate.getExpire(lockKey, TimeUnit.SECONDS);
        return (ttl != null && ttl > 0) ? ttl : 0L;
    }, 0L);
}
```

保留原 `isAccountLocked` 方法供内部使用。

### 2. 新增 `ResultCode` — `ACCOUNT_LOCKED` 已存在，无需改动

### 3. 修改 `AuthController.java` — 登录接口重写

```java
@PostMapping("/login")
public Result<LoginResponse> login(...) {
    String clientIp = RequestUtils.getClientIp(httpRequest);
    String userAccount = request.getUserAccount();

    // 1. 账号锁定检查（仅检查锁定状态，不记录次数）
    long lockRemaining = rateLimitService.getAccountLockRemaining(userAccount);
    if (lockRemaining > 0) {
        // 防枚举：确认账号存在后才返回锁定提示
        if (userService.existsByAccount(userAccount)) {
            throw new ServiceException(ResultCode.ACCOUNT_LOCKED,
                "账号已被临时锁定，请" + lockRemaining + "秒后重试");
        }
        // 账号不存在但有锁定记录（异常情况），跳过不暴露信息
    }

    // 2. IP 维度限速（防御分布式攻击）
    long ipResult = rateLimitService.checkIpRate(clientIp);
    setRateLimitHeaders(httpResponse, ipResult, ...);
    if (!RateLimitService.isAllowed(ipResult)) {
        if (RateLimitService.isLocked(ipResult)) {
            throw new ServiceException(ResultCode.IP_LOCKED, "...");
        }
        throw new ServiceException(ResultCode.TOO_MANY_REQUESTS, "...");
    }

    // 3. 调用 userService.login()（内部会检查账号级限流）
    LoginResponse data = userService.login(request, clientIp);
    return Result.success("登录成功", data);
}
```

### 4. 修改 `UserServiceImpl.java` — 移除重复的锁定检查

`login()` 方法中 line 88-96 的账号锁定检查已移到 Controller 层，需移除避免重复：

```java
// 删除这段（已由 Controller 处理）
long accountRate = rateLimitService.checkAccountRate(identifier);
if (!RateLimitService.isAllowed(accountRate)) {
    if (RateLimitService.isLocked(accountRate)) {
        throw new ServiceException(ResultCode.ACCOUNT_LOCKED, ...);
    }
    throw new ServiceException(ResultCode.TOO_MANY_REQUESTS, ...);
}
```

但保留 `checkAccountRate()` 调用（记录次数 + 分钟级限流）：

```java
// 保留：记录登录尝试次数（分钟级限流）
rateLimitService.checkAccountRate(identifier);
```

### 5. 新增 `UserService.existsByAccount()` 方法

```java
// UserService 接口
boolean existsByAccount(String userAccount);

// UserServiceImpl 实现
@Override
public boolean existsByAccount(String userAccount) {
    QueryWrapper<User> queryWrapper = new QueryWrapper<>();
    queryWrapper.eq(COLUMN_USER_ACCOUNT, userAccount);
    return this.count(queryWrapper) > 0;
}
```

## 登录流程图

```
请求进入
  ↓
检查账号是否锁定（Redis，~1ms）
  ↓
已锁定 → 检查账号是否存在（DB）
  ↓                    ↓
  存在                 不存在
  ↓                    ↓
返回"账号锁定"      跳过（不暴露信息）
+ retryAfter秒数     ↓
                  检查IP限流
                    ↓
              超限 → 返回"IP限制"
                    ↓通过
              调用 userService.login()
                    ↓
              记录登录尝试次数（分钟级限流）
                    ↓
              验证密码
                    ↓
              成功 → 清除计数器
              失败 → 计数+1
```

## 安全性验证

| 攻击方式 | 防御效果 |
|---------|---------|
| 暴力破解单账号 | ✅ 账号锁定优先拦截，显示 retryAfter |
| 枚举有效账号 | ✅ 账号不存在时返回相同错误，不泄露信息 |
| 分布式IP攻击 | ✅ IP限流作为第二道防线 |
| 同IP大量不存在账号 | ✅ IP限流拦截，返回模糊提示 |
